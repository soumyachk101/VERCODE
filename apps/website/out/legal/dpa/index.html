Data processing addendum

Last updated 2026-10-23 · Contact privacy@vercode.com

The data processed

What this addendum covers is the data an organization generates through the review pipeline: the findings (bounded code snippets), the usage record, and the audit event. Repository content itself is not processed beyond the review lifetime (NFR-28, the "repository content is ephemeral" rule; see the privacy policy for the full storage description).

The PII boundary

The organization's member emails and GitHub handles are PII under this addendum. The "no PII in logs" rule (NFR-22) applies across the error-tracking and observability stack: email addresses, code content, and secrets are scrubbed from breadcrumbs and captures before they are stored.

The subprocessor list

The AI provider acts as a processor under this addendum. The host (Vercel or Cloudflare Pages, an infra decision at launch) is a subprocessor for the website. A BYOK path reduces the AI subprocessor boundary for organizations that use their own provider key.

Deletion on revocation

When the GitHub App install is removed, the organization's data is hard-deleted on schedule (FR-404: deletion on access revocation). The deletion is a retention queue action, not a soft-delete; the 180-day audit floor is honored before the cascade completes.

The audit-log floor

Audit events are retained a minimum of 180 days under every tier (NFR-27: "audit log 180 days minimum"). The audit log is append-only — a mutation of the record is structurally impossible through the API; only a retention hard-delete expires an event by age. An audit retention below the 180-day minimum is a compliance defect.

The DPA is available to enterprise customers on request.
