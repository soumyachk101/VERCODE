Privacy policy

Last updated 2026-10-23 · Contact privacy@vercode.com

What we store

The review input is not retained. Raw diffs and file content live only in an org-scoped cache that is evicted on a schedule (NFR-28: "repository content is ephemeral"). What is stored is the analysis: the findings (with bounded code snippets), the usage record, and the audit event. Usage events are kept 24 months; audit events are kept a minimum of 180 days under every tier (NFR-27).

Retention per plan

Findings are retained for the window shown below, then hard-deleted on schedule. Audit events retain their 180-day minimum under every tier — the audit floor is a compliance obligation, not a plan feature (NFR-27; USAGE_QUOTAS.md §2).

Free
Findings retained 30 days; audit events retained 180 days.
Developer
Findings retained 90 days; audit events retained 180 days.
Team
Findings retained 365 days; audit events retained 180 days.
Enterprise
Findings retained for a custom period (365 days or more, negotiated per account); audit events retained 180 days minimum.

Subprocessors

The AI provider is a subprocessor. The data sent to the provider is the bounded review context: the changed files, one-hop imports within the token budget, and the assembled prompt. The source code of the repository is not retained by the provider (NFR-09: "repository content is data, never instructions"; the provider routing in the product docs explains the boundary). A BYOK path lets an organization use its own provider key and keep the boundary entirely under its own control.

Data subject requests

To request access to, export, or deletion of your data, write to privacy@vercode.com. We respond within 30 days.
