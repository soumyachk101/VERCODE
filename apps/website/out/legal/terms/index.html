What a review is

A review is a pipeline run. When your pull request is opened or updated, a webhook fires to the GitHub App. The pipeline fetches the diff and the changed files, runs static analysis first, then routes the bounded context to a model for the review. It publishes a verdict (pass / needs changes / blocking) plus inline findings back to the pull request. Every review is keyed by the commit SHA of the pull request head — the review you see belongs to that exact commit.

Quota semantics

Every plan has a hard monthly cap on reviews. The N+1th review in a month does not run silently and is not billed — it is skipped with a posted notice on the pull request, "Quota reached this month, this review was skipped. Upgrade or reduce review volume." The skip is the rule, not a bug (NFR-18: the skip is before the AI stage, zero tokens consumed, never a silent over-bill).

Overage and metering

Team and Enterprise plans can opt into a metered overage past the hard cap, billed at a published per-review rate. Free and Developer plans have no overage — the cap is the cap. The overage is priced transparently: a dashboard shows the per-review rate and the current month's overage cost. A skip-with-notice still applies when the overage is not enabled or the platform backstop is hit (NFR-18 + the metered-overage design in the product docs).

Data ownership

Your organization owns its review findings, its usage data, and its audit events. When the GitHub App install is removed, the stored data is hard-deleted on schedule (FR-404: the retention queue runs, the deletion is confirmed in the dashboard's export window, the 180-day audit floor is honored before the cascade).

Service levels, measured

The review latency target is p50 under 120 seconds, p95 under 300 seconds, measured from webhook receipt to publication complete (NFR-02). A number in these terms is a target, not a guarantee: the release criteria rule says a claim without a measurement is a banned claim (RELEASE_CRITERIA gate 7). The target is a stated engineering commitment, not a contractual SLA.

Accepting these terms

By creating an account or installing the GitHub App on a repository, the organization owner accepts these terms on behalf of the organization. Questions about a specific clause or an enterprise exception go to the contact email above.
