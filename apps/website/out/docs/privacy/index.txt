<p>VERCODE is a review system, not a code host: the analysis is the product, and the source code is transient input. A customer's full codebase is not stored as a durable asset — only the bounded, quoted snippet inside a finding, and even that is derived data, not a copy of the repository.</p>
<p>This page summarizes what is stored, for how long, and how deletion is enforced. The full privacy policy is at /legal/privacy/.</p>
<h2 id="what-is-stored-and-for-how-long">What is stored, and for how long</h2>
<div class="table-wrap"><table><caption>Data class, Retention, Notes</caption><thead><tr><th scope="col">Data class</th><th scope="col">Retention</th><th scope="col">Notes</th></tr></thead><tbody>
<tr><td>Findings + review history</td><td>30 d (Free), 90 d (Developer), 1 y (Team), custom (Enterprise)</td><td>The product value; expires on the plan's window, then a hard purge</td></tr>
<tr><td>Raw repo content</td><td>Ephemeral</td><td>Not stored beyond the review lifetime: a 24-hour cache, not a database column (NFR-28)</td></tr>
<tr><td>Usage events</td><td>24 months</td><td>Billing + analytics; append-only, age-hard-delete</td></tr>
<tr><td>Audit log</td><td>180 days minimum</td><td>The compliance floor (NFR-27); append-only</td></tr>
</tbody></table></div>
<p>A finding may quote a bounded snippet of the diff in its payload; the full file content is not written to the database. A schema gate asserts no raw-content column exists.</p>
<h2 id="what-is-not-stored">What is not stored</h2>
<ul>
  <li><strong>The full repository.</strong> The model receives a bounded context: the changed files plus one-hop imports, within a token budget, on the provider's no-training contract (NFR-29). The whole repository never reaches a provider.</li>
  <li><strong>Code-content telemetry.</strong> The usage analytics are about reviews, findings, and cost — not about which code patterns are common. There is no code-shape telemetry to a third party.</li>
</ul>
<h2 id="deletion">Deletion</h2>
<p>Deletion on access revocation is a first-class path (FR-404). Removing the GitHub App installation:</p>
<ul>
  <li>Marks the install removed and flags its repositories disconnected.</li>
  <li>Evicts the org's diff-cache entries immediately, and hard-deletes any embedding index.</li>
  <li>Opens a short export window for the org's findings before any hard-purge.</li>
</ul>
<p>The audit trail for a removed install keeps its 180-day minimum regardless. An org deletion is a soft-delete first (the data becomes unreadable but is preserved for a grace window), then a hard-purge cascade on the retention schedule.</p>
<p>Source: docs/DATABASE/DATA_RETENTION.md (the retention schedule + the FR-404 deletion); docs/SECURITY/PRIVACY.md (the data-minimization controls)</p>
