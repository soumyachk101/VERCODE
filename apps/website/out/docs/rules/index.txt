<p>Custom rules are the org's and the repo's control over which findings are published. A rule is versioned: each change is audit-logged and applies to the next review, not the in-flight ones. The rule types and their scope are the FR-505 surface.</p>
<p>The confidence floor is the primary knob: a finding under the floor is dropped before publication, so the pull request is not flooded with hedges. The default is 0.6 (FR-308).</p>
<h2 id="the-rule-types">The rule types</h2>
<div class="table-wrap"><table><caption>Rule, What it does, Scope</caption><thead><tr><th scope="col">Rule</th><th scope="col">What it does</th><th scope="col">Scope</th></tr></thead><tbody>
<tr><td>Confidence floor</td><td>Findings under the floor are not posted</td><td>org, or a single repo</td></tr>
<tr><td>Category suppression</td><td>An entire finding category is muted</td><td>org, or a single repo</td></tr>
<tr><td>Quiet categories</td><td>Low-severity categories are muted in a defined window</td><td>org</td></tr>
<tr><td>Per-language toggle</td><td>A language's review pass is enabled or disabled</td><td>org, or a single repo</td></tr>
</tbody></table></div>
<p>The deterministic static-analysis pass is exempt from the confidence floor: its precision is measured, not estimated, so the floor does not apply to it (FR-304).</p>
<h2 id="org-level-vs-repo-level">Org-level vs repo-level</h2>
<p>An org-level rule is the default for every repository in the org. A repo-level rule overrides the org default for that repository only. The precedence is repo over org: a repo that sets a category to suppressed keeps it suppressed even if the org default is to post it.</p>
<p>The two scopes answer different questions. An org-level rule is a policy: &quot;we do not want dependency-manifest findings posted anywhere&quot;. A repo-level rule is a local override: &quot;this legacy repo's generated files are noise, suppress them here&quot;.</p>
<h2 id="suppression-the-floor-and-the-skip">Suppression, the floor, and the skip</h2>
<p>Suppression and the confidence floor drop findings; a quota stoppage is a different control, the NFR-18 skip-with-notice. A rule never silences a quota skip: when an org is over its cap, the review is skipped with a notice on the pull request and a dashboard row, not quietly stopped. The rule surface and the quota surface are separate, and the skip is the only quota behavior a customer ever sees.</p>
<p>Rules are bounded by the plan: the number of custom rules an org can define is a plan quota (3 on Free, 10 on Developer, 50 on Team). A rule create over the cap is a 409 on the API and a dashboard notice.</p>
