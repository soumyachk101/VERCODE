<p>The dashboard API is a REST surface under <code class="mono">/api/v1</code>, JSON, authenticated by a signed HTTP-only cookie. The source of truth is <code class="mono">docs/API/API_SPECIFICATION.md</code> and <code class="mono">docs/API/OPENAPI.yaml</code>; this page summarizes the endpoint families and the conventions a caller needs to integrate.</p>
<p>The API is same-origin with the dashboard web app; the webhook routes are the public exception (no cookie, signature-verified).</p>
<h2 id="conventions">Conventions</h2>
<ul>
  <li><strong>Base:</strong> <code class="mono">https://&lt;host&gt;/api/v1</code>.</li>
  <li><strong>Auth:</strong> a signed, HTTP-only session cookie. Webhook routes are public and are verified by signature instead.</li>
  <li><strong>Authorization:</strong> every non-webhook route is tenant-scoped; a cross-tenant request is a 404, a capability miss is a 403.</li>
  <li><strong>Errors:</strong> a structured body, <code class="mono">{ &quot;error&quot;: { &quot;code&quot;, &quot;message&quot;, &quot;details?&quot; } }</code>. The code is stable and machine-readable; a client switches on the code, not the message.</li>
  <li><strong>Idempotency:</strong> mutating routes accept a client-generated idempotency key; webhook and payment routes dedupe on the provider's event id instead.</li>
  <li><strong>Pagination:</strong> cursor-based, <code class="mono">?cursor=</code> + <code class="mono">?limit=</code>.</li>
</ul>

<p>The full per-endpoint detail — request and response shapes, error codes, capability gates — is in the API specification; the OpenAPI file is the machine-readable form.</p>
<h2 id="the-webhook-contract">The webhook contract</h2>
<p>The GitHub webhook is the pipeline's ingress. Three lines cover its contract:</p>
<ul>
  <li><code class="mono">POST /webhooks/github</code> is public and HMAC-verified: an <code class="mono">X-Hub-Signature-256</code> header, a 5-minute timestamp window, and delivery deduplication (NFR-04, NFR-06).</li>
  <li>On a verified <code class="mono">pull_request</code> open/reopen/synchronize, the route enqueues a review job and returns 202; it does not fetch the diff or run the pipeline (the webhook's latency is constant regardless of review cost).</li>
  <li>A same-head-SHA re-delivery is a no-op by commit-SHA idempotency; a re-review of an open PR is a separate, explicit endpoint (<code class="mono">POST /orgs/:id/github/review</code>).</li>
</ul>
