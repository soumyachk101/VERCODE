<p>The GitHub App is the integration surface between VERCODE and your repositories. This page covers the install steps, the 5 permission scopes the App requests, and how repository discovery and removal work.</p>
<p>The App is installed per organization or per repository; the least-privilege scope list is fixed and is not expandable without a contract change (NFR-10).</p>
<h2 id="install-the-app">Install the App</h2>
<ol>
  <li>On the dashboard's repositories page, choose <strong>Install VERCODE</strong>. The install URL is generated server-side; the App is pre-scoped to the 5 permissions below, so the GitHub authorization screen shows only those.</li>
  <li>Authorize the install on GitHub and select the repositories the App should access.</li>
  <li>GitHub dispatches the <code class="mono">installation.created</code> webhook. VERCODE records the install for the org and discovers the connected repositories through the <code class="mono">installation/repositories</code> event (FR-202).</li>
</ol>
<p>The repositories page reflects the connected set immediately: each repository is listed with its status, and a newly added repository is reviewed on its next open pull request without any further configuration.</p>
<h2 id="the-5-scopes">The 5 scopes</h2>
<p>The App requests exactly 5 permissions (FR-210, the least-privilege list, verbatim from the PRD):</p>
<div class="table-wrap"><table><caption>Scope, Direction, What it permits</caption><thead><tr><th scope="col">Scope</th><th scope="col">Direction</th><th scope="col">What it permits</th></tr></thead><tbody>
<tr><td><code class="mono">contents:read</code></td><td>read</td><td>Fetch the diff and bounded file context at the PR's head SHA</td></tr>
<tr><td><code class="mono">pull_requests:write</code></td><td>write</td><td>Publish the summary comment and the inline findings</td></tr>
<tr><td><code class="mono">checks:write</code></td><td>write</td><td>Post the review's check-run status on the PR</td></tr>
<tr><td><code class="mono">metadata:read</code></td><td>read</td><td>Repository and PR metadata, for routing</td></tr>
<tr><td><code class="mono">issues:read</code></td><td>read</td><td>PR metadata (a pull request is an issue in GitHub's model)</td></tr>
</tbody></table></div>
<p>There is no <code class="mono">admin:org</code> and no secrets scope (NFR-10). The <code class="mono">pull_requests:write</code> scope is the only write in the set; it is the publication path, and nothing else in the App can write to your repositories.</p>
<h2 id="removing-the-app">Removing the App</h2>
<p>Removing the App is a first-class event, not an edge case. GitHub dispatches <code class="mono">installation.deleted</code>, and VERCODE handles it (FR-208):</p>
<ul>
  <li>The install is marked removed, and its repositories are flagged disconnected.</li>
  <li>A content-purge job is scheduled for that install: the diff cache is evicted immediately and any embedding index is hard-deleted. The deletion detail is on the <a href="/docs/privacy/">privacy page</a>.</li>
  <li>In-flight reviews for that install finish but do not publish; no further reviews are enqueued for it.</li>
</ul>
<p>Source: docs/PRODUCT/PRD.md (FR-210's scope list); docs/PRODUCT/FUNCTIONAL_REQUIREMENTS.md (FR-201..FR-208, FR-210)</p>
