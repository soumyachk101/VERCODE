<p>The security findings rollup is the org's triage view: one screen of open security findings across every connected repository, filtered by severity and by time. It is not a per-pull-request list; it is the answer to &quot;what is our security posture right now, and which PR does it come from?&quot;</p>
<p>The rollup is the FR-504 surface.</p>
<h2 id="what-the-rollup-shows">What the rollup shows</h2>
<ul>
  <li>Open security findings across all connected repositories, with the source pull request linked from each finding.</li>
  <li>A severity filter: the rollup's default view is severity ≥ high, and the full list is available on demand.</li>
  <li>A time filter: the rollup is a window over the finding set, not a cumulative backlog.</li>
</ul>
<p>Each finding carries the finding shape the pipeline publishes: a category, a severity, a confidence, a reason, a suggested fix, and the file + line it proves (FR-306 validates that the line location exists in the diff and that the category and severity are allowed values; an invalid finding is dropped, not posted).</p>
<h2 id="the-severity-model">The severity model</h2>
<p>The severity scale is four levels: <strong>critical, high, medium, low</strong>. The model is fixed and is not org-configurable — an org configures which severities it sees (the rollup filter), not what a severity means. A security-category finding is reviewed on the strongest model the plan's tier allows, and that pass is never downgraded for cost (the routing invariant in the model-routing doc, invariant 3).</p>
<p>The deterministic static-analysis pass produces the high-precision security findings: a Semgrep rule that flags an injection sink or a hardcoded credential is a measured check, not an estimate. The model's security findings are the delta on top of it.</p>
<h2 id="the-honest-limit">The honest limit</h2>
<p>The MVP does not execute the PR's tests; it analyzes the diff (L-1). The security findings are a static-analysis result and a model pass over the bounded context, not a dynamic test of the PR's behavior. A sandboxed execution that reports a test failure as a finding is the Phase 2 item; until it ships, the static pass is the stand-in, and this page says so plainly rather than implying otherwise.</p>
