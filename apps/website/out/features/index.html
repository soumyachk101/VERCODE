Features

The question this page answers: what does VERCODE do that a model-only AI reviewer does not? The short version — a pipeline that is deterministic first, evidence-backed, cost-disciplined, and a workspace around the pull request, not just a bot on it.

Deterministic precision

Static analysis runs before the model: ESLint, Semgrep, and secret scanning establish the ground truth on the changed files. The AI stage's findings are deltas on those grounded checks, not a free-form second opinion — a deterministic check that flags a pattern always does, and a model-only reviewer drifts run to run.

How it works

Evidence-backed reasoning

Every finding carries a category, a severity, a confidence, a reason, and a suggested fix — the ReviewFinding shape the pipeline publishes. The default confidence floor is 0.6: below it, a finding is suppressed, not down-ranked, so the pull request is not flooded with hedges. Each posted finding names its source stage and the file + line it proves.

Cost discipline

Per-org quotas and per-review cost accounting bound the spend. The static pass costs almost nothing; the task-routed AI stage sends the bounded diff, not the whole repo, and picks the model tier per task. An over-cap org's review is skipped with a notice, never silently billed beyond the cap.

A workspace, not just a bot

The dashboard answers the org's risk and cost question, not just the pull request's: a security rollup, an audit trail, a usage-vs-quota view. The review history is keyed by commit SHA, so both versions of a PR are legible. The PR comment is the output; the workspace is the product.

// the ReviewSummary shape the PR headline is built from
summary: {
  verdict: "Needs changes",
  highSeverityCount: 2,
  topRisks: ["SQL injection in payments.ts:84", "unbounded retry loop in workers/dispatch.ts:41"],
  overallConfidence: 0.87
}

Security findings rollup
