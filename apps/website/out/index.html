How it works

  1. Install the GitHub App

    The install URL is pre-scoped to the least-privilege list: contents:read, pull_requests:write, checks:write, metadata:read, issues:read. No admin:org, no secrets scope.

  2. Open a pull request

    GitHub dispatches the webhook; VERCODE verifies the signature and enqueues the review job in under 300 ms (NFR-04 — no LLM on the webhook path). The queue, not the request, does the work.

  3. Read the review

    Static analysis runs first; the task-routed AI stage runs on the bounded diff. A verdict and inline findings land on the pull request in under two minutes at p50 (NFR-02).

Built on four principles

Deterministic first

Static analysis — ESLint, Semgrep, secret scanning — runs before the model. The model's findings are deltas on grounded checks, not a free-form second opinion.

Evidence-backed

Every finding carries a category, a severity, a confidence, a reason, and a suggested fix. A verdict you can read, not a wall of flags to triage by hand.

Cost discipline

Per-org quotas and per-review cost accounting keep the spend bounded. The strong model runs only where it earns its spend; the static pass costs almost nothing.

A workspace, not just a bot

The dashboard answers the org's risk and cost question: a security rollup, an audit trail, a usage view. The pull request is one view of the org, not the whole product.

Questions

Does VERCODE post comments on my pull requests?
Yes. VERCODE posts a summary comment with the verdict and a severity count, plus inline comments anchored to the verified changed lines. If a line anchor fails validation, the finding is written into the summary comment instead of dropped. This is the FR-206 publication path.
How fast is a review?
A review publishes at p50 under 120 seconds and p95 under 300 seconds, measured from the webhook receipt to the GitHub publication, on a 50-file diff with 500 changed lines or fewer. That is the NFR-02 latency target. A diff past the file or line budget degrades to the highest-risk files rather than stalling.
Will it flood my PR with comments?
No. Findings under the confidence floor are not posted, and the floor defaults to 0.6 and is configurable per org and per repo (FR-308). You can also suppress an entire category for one repo. The deterministic static-analysis pass is exempt from the floor, because its precision is measured, not estimated.
What languages does it support?
VERCODE classifies each changed file by language and risk tier before the AI stage (FR-302). The classification is what routes the work: security-sensitive files, database-touching files, dependency manifests, generated code, and test files each get a distinct review treatment. A diff is reviewed file by file, not repo by repo.
Does it run my tests?
No. The pipeline analyzes the diff with static analysis and a model pass; it does not execute the PR's install or test steps. Running untrusted code in the product is a known-severity threat class, so it is closed by absence in the MVP (L-1). Sandboxed test execution is the Phase 2 item on the roadmap, and the known-limitations doc says so in plain terms.
