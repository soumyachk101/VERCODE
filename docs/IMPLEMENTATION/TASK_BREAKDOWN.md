# VERCODE — Task Breakdown

The task-level breakdown, *derived* from `IMPLEMENTATION_PLAN.md` (the milestones) — a *task* is a *coherent, committable* unit (a *a task ends with a verified state* + a *a next-task pointer*). The *task* *IDs* are *referenced by* the *`TRACEABILITY_MATRIX`* (a *task ↔ a FR ↔ a test*). A *task* is *not a milestone* (a *milestone is several tasks*; a *task is one commit's worth*).

## 1. The *task* *principle* (a *a task is a coherent, verifiable unit*)

- **A *task* ends with a *verified state*** (a *a task is "done" when its tests pass + its docs match + it's committed* — a *a task that's "coded but untested" is not done*, a *a task that's "coded but the docs drift" is not done* [a *`RELEASE_CRITERIA gate-11` the docs-drift*]).
- **A *task* is *small*** (a *one task is one file-cluster + one test-suite; a task that's a "build the whole pipeline" is a milestone, not a task*, a *`IMPLEMENTATION_PLAN §4 "commit in small, coherent units"`*).
- **A *task* has a *next-task pointer*** (a *a task's done state names the next task*, a *`PHASE 9 "identify the next concrete task"`*).
- **A *task* is *traced*** (a *a task ↔ a FR ↔ a test ↔ a doc*, a *`TRACEABILITY_MATRIX`* — a *a task with no FR or no test is a defect*).
